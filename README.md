# Route Story — загрузи трек, получи ролик

Загружаешь маршрут (GPX, TCX, KML, GeoJSON или CSV) — выбираешь стиль и формат — нажимаешь **«Скачать видео»** и получаешь готовый MP4 для Reels/Shorts (9:16) или YouTube (16:9). Всё в браузере: без сервера, без регистрации, файл маршрута никуда не загружается. Из голого трека продукт сам достаёт историю: откуда → куда, города по пути, время в дороге, высшую точку, профиль высоты, погоду того дня.

**Живая версия:** https://sander419.github.io/route-story-engine/ · **Готовые ролики:** [`exports/`](exports) · **Сценарий защиты:** [`docs/DEMO-SCRIPT.md`](docs/DEMO-SCRIPT.md)

Сделано для вайбатона Route Story: герой — кругосветчик на уницикле [@wahrider](https://t.me/wahrider), но продукт работает с любым треком.

## Проверить за минуту (путь жюри)

1. Откройте живую версию в Chrome или Edge. Сразу играет пример «День 47» — это не заранее записанный ролик, а отрисовка по данным в реальном времени.
2. Шаг **«Маршрут»**: выберите или перетащите свой файл (примеры лежат в [`samples/`](samples): [GPX](samples/samarkand-bukhara.gpx), [CSV](samples/ride-no-elevation.csv), [GeoJSON](samples/short-section.geojson)) либо нажмите «День из путешествия» или «Кругосветка @wahrider».
3. Шаг **«Вид»**: стиль — **Дневник** (по умолчанию), **Журнал V3**, **Атлас**, **Полночь** или **Навигатор**; формат — **9:16 · Reels, Shorts** или **16:9 · YouTube**.
4. Нажмите **«Скачать видео»**. Через 15–60 секунд под кнопкой появится ссылка на файл MP4 (H.264; без звука — встроенной музыки нет, можно приложить свою на шаге «Вид»).

На шаге **«Вид»** есть переключатель **«Рельеф в „Дневнике“»**: объёмный рельеф или плоский эскиз. Кнопки качества, языка карты и «Слои для монтажа» (прозрачные PNG/WebM для своего видеоредактора) — на шаге **«Ещё»**. Фото дня, имя героя, знак на карте и «Для кого серия» — на шаге **«История»**.

| Требование ТЗ | Как в продукте |

| 9:16 и 16:9 | отдельная компоновка каждого формата, не кроп |
| Готовый MP4 | экспорт покадровый (WebCodecs H.264), в Chrome/Edge — MP4; звука нет, если не приложена своя музыка; в браузере без WebCodecs — запасной WebM |

## Форматы входа

| Формат | Что читаем |
|---|---|
| **GPX** | `trkpt` в каждом `trkseg`, `rtept`, `wpt`: `lat`, `lon`, `<ele>`, `<time>` |
| **TCX** | `Trackpoint` в каждом `Track` |
| **KML** | `coordinates` и `gx:Track` (с `when`) |
| **GeoJSON** | `LineString`, `MultiLineString`, `Feature(Collection)`; высота — 3-я координата; время — `properties.coordTimes` / `times` |
| **CSV** | заголовок с `lat`, `lon` (+ `ele`/`alt`, `time`/`timestamp`); разделитель `,` `;` или Tab; десятичная запятая; без заголовка — порядок lat, lon, ele, time |

Если в файле нет времени или высоты, соответствующие кадры пропускаются сами. Как продукт обращается с «плохими» данными (проверяется тестами):
- **разрыв записи** (новый сегмент файла и прыжок от 1 км и от 20 обычных шагов): расстояние, скорость и набор высоты через него не считаются, линия через него не рисуется;
- **невозможный скачок высоты** (больше 40 м при уклоне круче ~150 %) набором не считается;
- **сбой GPS «в (0,0)»** отбрасывается;
- **180-й меридиан**: день и положение считаются по непрерывной долготе, трек не растягивается на весь мир;
- треки с десятками тысяч точек прореживаются до ~1800 по дистанции, форма маршрута и границы разрывов сохраняются;
- повреждённый или не маршрутный файл — понятная ошибка вместо падения.

## Честность данных

- Демо-путешествие «День 47» (Самара → Иркутск, 46 дней, 4 129 км) — **вымышленный путешественник на реальных дорогах OpenStreetMap**; время в демо-файлах смоделировано. Фото Байкала — Thomas D. Fischer, CC BY-SA 4.0, Wikimedia Commons (`media/demo/credits.json`).
- У героя @wahrider **нет настоящего GPX**: его путь — пунктирная схема по остановкам из публичных постов канала, с подписью в кадре. Километры — только «по словам автора» на названную им дату, промежуточные значения не выдумываются; у каждой остановки метка точности (`exact` / `city` / `region`, «≈» на карте). Реквизиты для донатов и личные данные в данные не попадают.
- В кадрах 9 фото героя из публичного канала (уменьшены до 800 px по большей стороне, подпись «Фото @wahrider · пост N», источники — `media/photos/credits.json`); только кадры без крупных лиц посторонних людей. Убрать все фото можно удалением папки `media/photos`.
- Погода — реальные данные [Open-Meteo](https://open-meteo.com/) (архив ERA5) по координатам и дате из файла. Если в файле нет времени, погода не показывается и в панели так и написано.
- Барбос в «Дневнике» — иллюстрация по фото героя (пост 243, конфигурация без багажа): зелёный обод, протектор, дисковый тормоз, угловой руль, клетка и багажник сверены с фото; конструкция не придумывалась. Показывается только для героя и тех, кто выбрал знак «Уницикл».
- Стикер страны в кадре прибытия — **культурный предмет как контекст страны** (юрта, чайный стакан, квеври…), а не заявление, что автор побывал у конкретного объекта; страна берётся из геокодера. Стикер достопримечательности — только при подтверждённом событии (Шылпык, пост 407). Стикеры ветра и дождя — только если погода из данных это подтверждает (ветер от 3 м/с, осадки от 2 мм).
- Рельеф в «Дневнике» — настоящие высоты, но с вертикальным преувеличением ×3 (подпись в кадре): без него равнинные маршруты выглядят плоскими. Трек рисуется поверх рельефа и не прячется за хребтами. Нет сети или WebGL — «Дневник» рисует плоский эскиз настоящей геометрии без карты: разрывы записи не соединяются, пунктир героя остаётся пунктиром.
- Чего нет в данных — того нет в кадре.

## Внешние сервисы и приватность

Файл маршрута разбирается в браузере и не загружается на сервер. Стиль «Дневник» не рисует карту и не обращается к серверу карты вообще. Для названий, страны и погоды (и карты в остальных стилях) браузер обращается к внешним сервисам, и **часть координат (старт, финиш, несколько точек по пути) уходит им в запросах**:

| Сервис | Зачем | Что уходит |
|---|---|---|
| [OpenFreeMap](https://openfreemap.org/) | векторные тайлы карты (данные OpenStreetMap) | номера плиток в зоне маршрута |
| [Nominatim](https://nominatim.openstreetmap.org/) | названия старта и финиша | координаты нескольких точек |
| [Open-Meteo](https://open-meteo.com/) | погода того дня | координаты и дата трека |
| AWS Terrain Tiles | высоты для рельефа в «Дневнике» | номера плиток (область вокруг маршрута, не более 4×4 плиток; на телефоне 3×3) |

Шрифты хранятся в проекте ([`fonts/`](fonts), 302 КБ) и из сети не грузятся. Без сети карты в стилях Журнал V3, Атлас, Полночь и Навигатор не будет; «Дневник» экспортируется полностью даже при заблокированных карте, Nominatim и Open-Meteo (проверено: ролик 9:16 Full HD за 9 секунд, без названий и погоды), а при недоступных высотах — с плоским эскизом вместо рельефа. Без Nominatim и Open-Meteo остальные стили тоже экспортируются, но беднее. Если нужна страховка от плохой сети — готовые ролики лежат в [`exports/`](exports).

## Как устроен экспорт

Экспорт **покадровый**, а не запись экрана: каждый кадр рисуется на canvas по таймкоду, кодируется через WebCodecs (`VideoEncoder`, H.264) и упаковывается в MP4 библиотекой [mp4-muxer](https://github.com/Vanilagy/mp4-muxer) (если приложена своя музыка — со звуком: файл декодируется, подрезается под длину ролика и кодируется в AAC). Поэтому результат не зависит от нагрузки компьютера и получается быстрее реального времени; перед рендером нужные тайлы карты догружаются. Измерено: Full HD 9:16 на ролике 37 с — 24 с, трейлер на 45 с — 31 с, трек на 22 000 точек в 720p — 56 с.

Рельеф стоит дёшево: кадр около 1 мс на видеокарте и ~50 мс без неё (программный WebGL, 131 тыс. треугольников, 1080×1920), это примерно +1 минута на ролик без видеокарты; высоты и текстура считаются один раз на маршрут (≈1 с, по ≤16 плиткам).

**На телефоне** интерфейс работает в один столбец, свой файл выбирается кнопкой, по умолчанию HD 720 (Full HD — в «Ещё → Качество»), область рельефа меньше (3×3 плитки, сетка 193×193). Проверено эмуляцией Android с замедленным в 4 раза процессором: ролик 42 с в HD 720 экспортируется за 15 с (с видеокартой). Настоящий телефон не проверялся; в Safari/iPhone без WebCodecs запись идёт через MediaRecorder в MP4 (без звука, в реальном времени).

Работает в Chrome / Edge / других браузерах на Chromium. Если браузер не умеет H.264 через WebCodecs (Firefox, Safari), превью работает, а экспорт идёт запасным путём — WebM через `MediaRecorder` в реальном времени, **без звука и без длительности в заголовке** (такой файл не перематывается). Настоящие Firefox и Safari не проверялись: запасной путь проверен имитацией браузера без WebCodecs.

Карта рисуется **на обычном 2D-холсте** собственным рисовальщиком (`src/vector.js`) из тайлов OpenFreeMap: без WebGL и без видеокарты, поэтому ролик собирается одинаково на любом ноутбуке.

## Запуск локально

Сборки нет, нужен любой статический сервер:

```bash
git clone https://github.com/sander419/route-story-engine
cd route-story-engine
python -m http.server 4180
# открыть http://localhost:4180
```

Полный клон около 1,6 ГБ (в истории лежат старые версии роликов); для проверки хватит `git clone --depth 1` (≈370 МБ, из них 353 МБ — ролики в `exports/`).

## Ограничения (честно)

- Встроенной музыки нет (убрана по решению автора): ролик без звука, пока не приложена своя музыка.
- Готовые ролики в `exports/` сделаны до появления стиля «Дневник» (Атлас и Полночь); ролики в новом стиле — отдельным шагом.
- Нет офлайн-подложки: без интернета карта не грузится.
- Вне Chrome/Edge экспорт — запасной WebM без звука (см. выше).
- Если у демо-путешественника в файле смоделированное время, погода «того дня» — реальная погода на ту дату в том месте, а не запись поездки.
